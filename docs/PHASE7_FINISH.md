## 1. カメラを右上へ、ロケットを 4 つめの席へ

### 配置
```
レバー ひだり（いつもの配置）
┌──────────────────────────────────────────────┐
│[にもつ]           [ はやさ ]          (カメラ)(||) │ ← 52px の丸 2 つ、すきま 12px
│              [ ていしゃ ゲージ ]  [カメラの えらぶ板]│ ← 右上の下にひらく
│┃レバー┃                         (ライト)(ロケット) │
│┃      ┃                         (ジャンプ)(きてき) │
└──────────────────────────────────────────────┘
レバー みぎ（左ききの配置）
│(||)(カメラ)          [ はやさ ]          [にもつ]│
│[カメラの えらぶ板]                              │
│(ロケット)(ライト)                     ┃レバー┃ │
│(きてき)(ジャンプ)                     ┃      ┃ │
```
- 一時停止は今の隅から動かさない。カメラはその内側に置く（右利き `right: safe-right + 80px`、左利き `left: safe-left + 80px`、高さは一時停止と同じ `top: safe-top + 12px`）。
- 置いた場所どうしはぶつからない。荷物の帯は反対の隅にあり、「はやさ」と停車ゲージは真ん中にある。停車ゲージは 1194 幅で x 277〜917、カメラの丸は x 1062〜1114。
- カメラの丸は絵だけにする（aria-label は「カメラ」）。押すと今と同じ 4 枚の選ぶ板が出る。板は隅の下 `top: safe-top + 76px` に、一時停止と同じ端にそろえて横 1 列でひらく。背の低い画面（`max-height: 500px`、iPhone SE）では板を 80×72 に小さくする。板を選ぶか、ほかの場所をタップすると閉じる（今と同じ）。
  - 開いた板は 停車ゲージと同じ高さに かかる（iPad では停止線の下半分、小さいスマホでは ほぼ全部）。板は画面の上の DOM の いちばん はじめに置き、停車ゲージ（と吹き出し・暗転）が 板の上に描かれるようにした（ゲージは さわれないので、下の板は そのまま押せる。実装で決めた）
- ロケットは、前にカメラがあった「上の外側」の席に入る。
  - きてきとジャンプは、子どもがもう覚えた場所から動かさない。
  - ロケットは坂のふもとなどで落ち着いて押すボタンなので、一瞬を争うジャンプに一番押しやすい「下の内側」を残す。
  - ロケットを覚える前は、その席が空いたままになる（1-1 はきてき 1 つだけ）。
- ロケットの丸は見た目と押し口だけをここで決める。しくみそのものは 2-3 の設計で決める。
  - ふちの輪がゲージ（今のクールダウンの輪を使う）。
  - 噴かしている間は `data-boost=1` で炎がゆれ、押しても何も起きない。
  - ゲージが空か「ロケット禁止」の区間では `data-idle=1` で灰色になる。押すとピコのせりふ（`lines.rocketNo`）だけが出る。
  - 「いま！」のときは `data-glow=1` で光る。
  - 押し方は pointerdown で 1 回押すだけ。長押しはしない。

## 2. 重い場面の軽量化

### 測ったこと
- 日付と条件: 2026-09-25。開発ビルド、手元の Chromium（ソフトウェア描画）、1194×834、倍率 1。
- 方法: 電車を 50 m ごと（駅の近くは 20 m ごと）に置き、カメラを合わせて 1 コマ描く。そのときの描画回数と三角形の数を、モデルごとに数えた。
- 使ったスクリプト: 仕上げ PR1 で `scripts/probe-budget.mjs`（`npm run budget`）として入れる。
- この方法だと、スモークの通しより重い場面を拾う。前に出ていた「約 203 回／約 11.4 万」との違いはそのため。

| 場面 | 一番重いコマ | 予算 |
|---|---|---|
| 1-1 よこから | **250 回**・7.0 万（s=300） | 200 回・10 万 |
| 1-1 うしろから | 190 回 | |
| 1-2 うんてんせき（きょうりゅうえきの手前 s=550） | 168 回・**11.3 万** | |
| 1-2 うしろから（s=640） | **208 回・12.6 万** | |
| 1-3 うしろから／うえから | 186 回／183 回 | |
| 2-1（どのカメラでも） | 164 回・6.1 万まで | |

**1-1 よこからの内訳（250 回）**
- 町の家と木: 104 回（house-a は 8 色 × 3 区画で 24 回など）
- 駅 4 つ: 80 回（1 駅 20 回 = ホーム 6、屋根 5、駅名板 4、とまれ板 4、白線 1）
- 踏切: 4 回
- 電車とピコ: 44 回（先頭 15、客車 10×2、ピコ 9）
- 線路 8 回、猫と乗客 8 回、空と地面 2 回

原因: GLB のマテリアルは色だけで、絵（テクスチャ）がない。それでも「1 色 = 1 回」で描いている。

**1-2 うんてんせき s=550 の内訳（11.3 万）**
- 翼竜の群れ 2.86 万（13 羽 × 2,200 三角形）。群れは画面の外にいても毎回描く設定（`frustumCulled = false`）。
- 崖 2.9 万、ソテツ 0.95 万、シダ 0.71 万、恐竜 4 頭 1.73 万、線路 1.18 万。
- 描画回数 168 の内訳: 地形 95、駅と恐竜など 52。

### 直し方
**A. 色を頂点に焼いて、1 回で描く（全ステージに効く。いちばん大きい）**
- 新しいファイル `src/view/three/bake.ts` を作る。
  - 対象: 絵がなく、不透明なマテリアルだけでできたモデル。町・駅・谷・電車・ピコの GLB と、コードで描いた仮のモデルがこれに当たる。
  - 部品を全部 1 つの形にまとめる。各頂点に `color`（マテリアルの色）と `bakedRoughness` を持たせ、uv は捨て、index のあるなしをそろえる。
  - マテリアルは共通の `MeshStandardMaterial({ vertexColors: true, metalness: 0 })` を 1 つだけ使う。onBeforeCompile で roughness を頂点から読む（15 行ほど）。これで見た目は今と同じになる。
  - 絵のあるモデル（恐竜、猫、翼竜、サカサ）は今のまま。
  - 作った結果は、元のモデルごとに WeakMap で覚えておく（`merged` と同じやり方）。
- `src/view/three/props.ts` の `sourceMeshes()`: 焼けるモデルは焼いた 1 つを返す。これで「モデル × 区画」ごとに 1 回になる。
- `src/view/three/actors.ts` の `addStations()`: 1 駅の部品 5 つを 1 つに焼く。1 駅 1 回で描き、見えない駅は駅ごとに描かない（今のコメントの方針のまま）。踏切も焼く。
- `src/view/three/ThreeSceneView.ts` の `init()`: 電車・客車・ピコを焼く。どれも動かすのは丸ごとだけ。ドアの帯やライトの光は別の物なので影響しない。
- 減る量: 1-1 よこからで −76（町）、−79（駅と踏切）、−40（電車）。1-2 で −55（地形）、−30（駅）。

**B. 区画を細かく（150 m → 75 m）**
- `props.ts` の `CELL = 75` にする。A のあとは 1 区画 1 回で済むので、細かくしても安い。そのぶん画面の外のものを描かずに済む。
- 見積もり（probe2）:
  - 1-2 s=550: 地形 4.67 万 → 3.91 万（−0.76 万）。
  - 1-2 s=640: 5.32 万 → 4.05 万（−1.27 万）。
  - 描画回数は 30 → 40 回に少し増えるが、それでも少ない。

**C. 翼竜の群れ（1-2）**
- `src/view/three/abilities.ts` の `Flocks`: 群れの円ぜんぶを包む大きさを固定で決めて、`frustumCulled = true` にする。カメラの後ろにいる群れは描かなくなる。
- 遠く用の軽い翼竜 `ptero-far` を作る。
  - 400 三角形以下、1 色で絵なし、形は同じ。群れはいつも 40 m 以上離れているので、見分けはつかない。
  - `assets/blender/dinos.py` に足し、`assets/models.json` に書く。
  - `src/stages/1-2.json` の群れを `"model": "ptero-far"` にする。
- 減る量: 見えているときで 2.86 万 → 0.39 万（−2.47 万）。軽くなるので、群れを前の 10＋8 羽に戻せる（0.72 万）。

**D. （してもしなくてもよい）** ソテツを 868 → 約 450 三角形にする（`valley.py`、葉の段を減らす）。−0.3 万。
