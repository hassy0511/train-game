## 3. 地図

### データ
`src/world/world.json`（ステージの JSON とは別。ステージ固有の値ではなく、世界全体の並び）:
- `islands[]`: `id`（ステージ id）、`chapter`、`x`・`y`（地図の中の位置、% ）、`diorama`（島の絵に並べるもの）
- `links[]`: `[from, to]`。`from` をクリアすると線路が敷かれる
- ステージのファイルがまだない島（2 章）は「？」の影で出す。タップしても揺れるだけ

### 島の絵
- `node scripts/render-map.mjs` が、ゲームと同じモデル（まだないものはコードで作った仮の形）を島の上に並べて描き、`public/map/<id>.png` に書き出す。透明の背景、余白は切り詰める
- 並べ方は `world.json` の `diorama`（モデル名、島の上の位置 [x, z] m、向き、大きさ）
- 描く道具のページは `tools/map-render.html`（開発用。ゲームのビルドには入らない）
- 本物のモデルが増えたら（チケット 0006 など）、スクリプトを流し直すだけで絵が新しくなる

### 画面
- 空の色の背景に島が浮かび、島の間を線路（まだのところは白い点線）がつなぐ
- 島: 絵、名前（クリアしたら ★）、「きろく 見つけた数/全部」。後の能力が要る記録が残っていれば「？」を添える
- まだ行けない島は色を薄くし、タップすると揺れるだけ
- 次に行く島は、ぴょこぴょこ動く
- 新しく敷かれた線路は、地図を開いたときに一度だけ伸びていく（見せたものはセーブの `mapLinks` に残す）

### 流れ
- ステージをクリアして「つづく」→ 地図。線路が伸び、次の島が動く → タップでそのステージへ（タイトルは通らない）
- 地図の左上は「タイトルへ」
- タイトル画面の「ちず」からも開ける（左上は「もどる」）。行ける島をタップするとそのステージへ

## 4. 一時停止と設定
- 「||」は右上に小さく（左利きの配置では左上）。押すとゲームの時間が止まり（せりふの待ちや演出も止まる）、「ひとやすみ」の画面で「つづける」「ちずに もどる」。地図の「もどる」でこの画面に戻る。地図で島を選ぶとそのステージへ（今のステージの途中経過は残らない）
- 設定はタイトル画面の右上の歯車からだけ（遊んでいる子が途中で触らない）。押したらすぐ効いて、すぐ保存
  - おんがく／こうかおん: けす・ちいさく・おおきく
  - がめんの ゆれ: あり・へらす（へらす = 急ブレーキや失敗のときの画面のゆれと沈み込みを止める）
  - レバーの ばしょ: ひだり・みぎ（みぎ = レバーを右、ボタンのかたまり・吹き出し・カメラの選択を左へ。左利き向け）
- 設定は進み具合のセーブとは別に保存する（`train-game.settings.v1`）。片方を消しても、もう片方は残る。セーブのスキーマは 1 のまま（地図の `mapLinks` は省略可の項目として足した）

## 5. 音
- 曲は音の並びをデータ（`src/audio/songs.ts`）で持ち、Web Audio の電子音で鳴らす（`src/audio/music.ts`）。音源ファイルなし、すべてオリジナル。実在の曲・発車メロディに似せない
- 書き方: `"C5:2"` = 音の高さと長さ（ステップ数）、`"-:2"` = 休み、`k`/`s`/`h` = 太鼓・スネア・シャカシャカ。1 曲の全パートは同じ長さにして、くり返す
- 楽器（電子音）: `lead`（おもちゃの笛）、`bass`、`bell`（オルゴール）、`wood`（木琴）、`pad`（やわらかい伴奏）、`drums`
- 曲
  | 名前 | 使う場所 | 感じ |
  |---|---|---|
  | `title`「そらの ちず」 | タイトル、地図 | オルゴールの 3 拍子 |
  | `town`「まちの あさ」 | 1-1 | 明るい 2 拍子の行進 |
  | `valley`「シダの たに」 | 1-2 | ゆったり、低い木琴 |
  | `sky`「くもの うえ」 | 1-3 | ふわふわの 6/8、高いベル |
- ステージの曲はステージ JSON の `environment.bgm` に名前を書く（v1 からあった欄。知らない名前はエラー）
- iPad は最初のタップまで音が出せないので、曲は最初のタップで始まる。一時停止の間は曲も止まる。音量は設定の「おんがく」
- 効果音を足した: クリアのファンファーレ、記録を見つけたときのきらきら音
- 聴いて確かめる: `node scripts/render-music.mjs <出力先>` で 4 曲を WAV に書き出す（`tools/music-render.html`、開発用）

## 6. 速さ
- **描画の細かさの自動調整**: 1 秒あたりのコマ数が 3 秒続けて 45 を下回ったら、描画の細かさ（1 ピクセルに描く点の数）を 2 → 1.5 → 1.25 → 1 と 1 段ずつ下げる。一度下げたら、そのページの間は戻さない（行ったり来たりしない）。値は `src/train/params.ts` の `RESOLUTION_*`
- **重さの記録**: 1 コマで描く回数（ドローコール）と三角形の数の最大値を `#app` の `data-draws-max` / `data-tris-max` に出し、1-1〜2-1 の通しのスモークがログに書く。予算（TECH_SPEC §6: 200 回・10 万三角形）を超えたらテストを失敗にする
- **測ってみたら予算を超えていたので減らした**（最初の 25 秒の最大値。2026-09-25、手元の Chromium）

  | ステージ | 前 | 後 |
  |---|---|---|
  | 1-1 | 172 回・6.0 万 | 174 回・5.3 万 |
  | 1-2 | 204 回・13.7 万 | 161 回・9.6 万 |
  | 1-3 | 239 回・8.0 万 | 184 回・6.7 万 |

  - 線路（レール・砂利・枕木）を 100 m ごとの 1 つのかたまりにした（色は頂点に持たせる）。見えない区間は描かない。前は線路 1 本が丸ごと 1 つで、いつも全部描いていた
  - 霧の先は描かない（カメラの届く距離 = 霧が濃くなりきる距離 + 40 m。空の球はその内側に縮める）
  - 同じ色の部品を 1 つにまとめてから並べる（コードで作った仮の雲や島が、小さな球の数だけ描かれていた）
  - 翼竜の群れを 1 回で描く（1 羽ずつ描いていた）。1-2 の群れは 10＋8 羽 → 7＋6 羽（翼竜のモデルが 1 羽 2,200 三角形と重いため。軽いモデルができたら戻せる）→ その後、遠く用の `ptero-far`（380 三角形）で 10＋8 羽に戻した（下）
- **全部の場面を測り直して、さらに減らした**（2026-09-25、`docs/PHASE7_FINISH.md` §2）
  - 測り方: `npm run budget`。電車を線路 50 m ごと（駅の前後 60 m は 20 m ごと）に置き、4 つのカメラで 1 コマずつ描く。上の「最初の 25 秒」より重い場面を拾う
  - 開発ビルド、手元の Chromium（ソフトウェア描画）、1194×834、倍率 1。どのステージもオープニングの前（役者は置いた場所のまま）

  | ステージ | 前（描く回数・三角形） | 後: 描く回数の最大（カメラ、場所） | 後: 三角形の最大（カメラ、場所） |
  |---|---|---|---|
  | 1-1 | 250 回・7.0 万 | 53 回（よこから s=300） | 7.0 万（よこから s=300） |
  | 1-2 | 208 回・12.6 万 | 75 回（うしろから s=650） | 9.2 万（うしろから s=580） |
  | 1-3 | 186 回 | 82 回（うしろから、線路 `flip` の s=150） | 6.4 万（うえから、線路 `flip` の s=300） |
  | 2-1 | 164 回・6.1 万 | 57 回（うしろから s=0） | 6.2 万（うしろから s=25） |

  - 色を頂点に焼いて、1 つのモデルを 1 回で描く（`src/view/three/bake.ts`）。町・駅・谷・電車・ピコ・踏切・役者が対象。絵のあるモデル（恐竜・猫・サカサ）はそのまま
  - 置き物をまとめる区画を 150 m → 75 m にした（画面の外の区画を描かずに済む）
  - 翼竜の群れ: 遠く用の軽いモデル `ptero-far` に替え、群れの円ぜんぶを包む球を決めて、カメラの後ろにいる群れは描かない
  - 通しのスモーク（本番ビルド、全ミッション）の最大は 1-1 44 回・5.6 万、1-2 73 回・8.2 万、1-3 82 回・5.8 万、2-1 58 回・6.0 万
  - いちばん余裕が少ないのは 1-2 のうしろから（崖 2.7 万、線路 1.2 万、ソテツ 0.9 万、恐竜 1.8 万）。1-2 に物を足すときは `npm run budget` で確かめる
